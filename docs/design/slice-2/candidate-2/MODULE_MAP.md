## What each module owns

| Module | Knowledge that it owns | Does I/O | Imports from the package |
| --- | --- | --- | --- |
| `dashboard.py` | Which slots a check should have; how probe rows fold into one mark; when the worker is stalled; the JSON shape of the API | No | `domain`, `verdict` |
| `store.py` | All SQL. Binning rows into slots with `date_bin`, and counting them. The read-only session | Postgres | `domain`, `verdict`, `dashboard` |
| `web.py` | Routes, status codes, cache headers, static files, the account of a request | HTTP | `config`, `dashboard`, `store` |
| `cli.py` | The command names | Terminal | `config`, `dashboard`, `web` (lazy) |
| `web/src/api.ts` | The poll period, the stale rule, the HTTP call | HTTP | generated types |
| `web/src/strip.ts` | How slots become pixel columns | No | generated types, `marks` |
| `web/src/marks.ts` | Colors, labels and the column priority (display only) | No | generated types |

`dashboard.py` owns every rule that gives a number or a mark. The TypeScript side owns only display: color, text, and the down-sample of columns. No TypeScript code computes an uptime, a mark, or a stall.

## Data flow of one poll

```
browser: useDashboard, every 60 s or on tab focus
  GET /api/dashboard                                         web.py
    reader.dashboard_facts(current_account(settings), clock())   store.py
      BEGIN REPEATABLE READ READ ONLY
        _MONITORED_CHECKS                 -> MonitoredCheck per check
        check_windows(check, now)         -> CheckWindows    (dashboard.py, pure)
        _STRIP_TALLIES  (lo, hi = strip)  -> {slot_start: VerdictTally}
        _WEEK_BUCKETS   (lo, hi = week)   -> [TallyBucket]
        _LATEST_SLOTS                     -> LatestSlot
        _PROBE_ACTIVITY                   -> ProbeActivity per probe
      COMMIT                              -> DashboardFacts
    build_dashboard(facts)                -> Dashboard       (dashboard.py, pure)
  200 JSON (gzip)
DashboardView(state)                      -> WorkerBanner, CheckRow x n, SlotStrip
```

Three Python files from the request to the response: `web.py`, `store.py`, `dashboard.py`.

## Test plan

| Layer | File | What it proves | Needs |
| --- | --- | --- | --- |
| Rules | `tests/test_dashboard.py` | Expected slots for intervals that do and do not divide a day; check life; pending and not observed; fold; ratio excludes not observed; worker states; Python sort order | Nothing |
| Store | `tests/test_store_dashboard.py` | `date_bin` equals `Slot.containing`; tallies with two probes; week buckets; interval change; account isolation; read-only session; the index is used | Compose Postgres |
| API | `tests/test_web.py` | 200 body parses as `Dashboard`; 405 on writes; 503 when Postgres is down; schema and fixtures do not drift; Compose binds 127.0.0.1 | Compose Postgres |
| Front end | `web/src/test/*.test.ts(x)` | Column down-sample keeps one down slot; runs; ages from `as_of`; stale and failed states; stall alert first | Node, jsdom |
| Browser | `tests/test_browser.py` | Real page in Chromium: order, stall alert, alert clears after a new row and one poll | `web/dist`, Playwright Chromium |

All tests run offline with no credentials. The browser test is the one end-to-end check.
